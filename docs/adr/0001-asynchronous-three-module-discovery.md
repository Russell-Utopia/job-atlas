# 使用异步三模块岗位发现流水线

Job Atlas 对外采用 `StartDiscovery / GetDiscovery / RestartDiscovery` 异步 Interface，对内由规划模块通过持久化工作队列编排“城市范围到企业信息、企业信息到具体岗位页面、岗位页面到最终岗位”三个深模块。这样可以在长时间、多来源扫描中增量交付已确认岗位并独立重试失败工作，同时把企业来源、官网、招聘列表和 ATS 的差异隐藏在模块内部，避免规划模块依赖一串浅步骤。

## Consequences

- 对外岗位始终只有 `companyName / title / city / jd / applyUrl`，内部来源与审计事实不进入岗位结果。
- `completed` 只承诺本次已启用来源扫描结束，不承诺现实世界的绝对全集；未完成的已启用来源使任务 `blocked`。
- 第一版 OSM Adapter 直接扫描城市行政边界内命中声明规则的企业候选，不以发现产业园作为必经步骤，也不把 OSM 候选称为城市工商企业全量。
- 第一版不启用企查查、天眼查或政府企业数据；未来启用 Adapter 不改变三个业务模块和对外 Interface。
- `OfficialJobDiscovery` 的内部调用方根据已经确认的招聘来源类型选择解析策略；解析策略不接收上游完整企业信息，也不负责岗位输出判断。
- 同一来源岗位 ID 不变时更新当前岗位事实，不保存旧页面或旧 JD；失败与重试只保留不含旧 JD 的执行记录。
